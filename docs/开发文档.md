## 1. 项目背景与目标

### 1.1 背景

- 发起人本人想戒烟，同时希望做一个小程序帮助同类人群。
- 市面上大量戒烟产品停留在「打卡 + 恐吓式科普」，对真正的高危时刻（渴求发作、社交递烟、饭后、饮酒）帮助有限。
- 研究显示：App 单独使用效果不确定；App 与药物/行为支持结合时效果显著。因此产品定位不应是「替代治疗」，而应是「行为支持工具 + 医疗导流入口」。

### 1.2 产品目标

1. 在用户**想抽烟的那一刻**提供可立即执行的 3–5 分钟干预。
2. 帮用户识别自己的**高危触发场景**，形成个人化应对方案。
3. 把需要药物或专业帮助的用户**导流到戒烟门诊/热线**，而不是让 App 假装能治病。
4. 对复吸友好：记录、归因、重新开始，而不是羞辱和清零。

### 1.3 成功指标（待确认）

| 指标 | 说明 |
|---|---|
| 7 日点戒烟率 | 初次使用后 7 天未吸烟 |
| 30 日持续戒断率 | 主要疗效指标 |
| 渴求急救使用率 | 有渴求记录的用户中，使用急救的比例 |
| 急救后 30 分钟复吸率 | 衡量急救是否真的有用 |
| 次周留存 / 文档完成率 | 依从性代理指标 |
| 医疗导流点击率 | 进入戒烟门诊/热线页面的比例 |

> 指标口径与统计周期需在 MVP 评审时确定。

## 2. 目标用户与核心场景

### 2.1 用户分层

| 分层 | 特征 | 核心需求 |
|---|---|---|
| 主要用户 | 每日吸烟、有戒烟意愿、反复失败 | 熬过渴求、找到替代、别再复吸 |
| 次要用户 | 计划戒烟但未定日期 | 评估依赖、设定戒烟日、准备 |
| 次要用户 | 已戒烟 1–12 个月，防复吸 | 高危场景预警、复吸复盘 |
| 延伸用户 | 吸烟者家属 | 理解、支持、避免说教式施压 |

### 2.2 核心场景（按优先级）

1. 饭后、饮酒、咖啡后
2. 工作压力大、焦虑、烦躁
3. 社交场合被递烟
4. 独处、无聊、刷手机
5. 起床后第一支、如厕、开车、打电话
6. 打牌/麻将/游戏间隙
7. 复吸后的自责时刻

## 3. 研究结论：烟瘾机制

> 证据等级说明：「高」= 指南/Cochrane 级别；「中」= 系统综述/Meta 分析；「推断」= 基于机制的产品设计假设，非临床结论。

### 3.1 四层机制

| 层次 | 机制 | 对产品的含义 |
|---|---|---|
| 药理层 | 尼古丁与 α4β2 受体结合，促进多巴胺释放；半衰期约 2 小时；耐受与戒断 | 需要药物时导流；急救要覆盖戒断症状；不能承诺「靠意志力」 |
| 条件反射层 | 场景/线索与吸烟配对，触发渴求；生理戒断结束后仍可持续数月 | 触发日志、场景预警、替代行为是核心 |
| 情绪层 | 压力、焦虑、抑郁、无聊、孤独；尼古丁被当作情绪调节工具 | 急救需包含情绪调节（呼吸、正念、行为激活） |
| 社会/习惯层 | 同伴、家庭、递烟文化、价格可及性；基底节自动化 | 拒绝话术、社交支持、环境改造清单 |

### 3.2 关键事实

- 中国 15 岁及以上人群现在吸烟率 **23.2%**，男性 **43.9%**；吸烟人群戒烟率 **22.6%**；现在吸烟者日均 **15.8 支**。[高]
- 单靠意志力戒烟，一年成功率通常约 **3%–5%**。[中]
- 复吸诱因（中国男性研究）：社交场合 34.3%、负性情绪 13.4%、正性情绪 13.4%、独处 8.4%、饭后 7.4%、娱乐 5.9%、压力 4.4%、饮酒 1.9%。[中]
- 渴求通常在几分钟内达到峰值，5–10 分钟内回落；「熬过这一波」比「永远不想抽」更现实。[临床常识/中]

### 3.3 对产品的直接启示

1. **不要做纯打卡**：打卡记录的是结果，急救解决的是过程。
2. **触发识别优先于意志力训练**：用户需要知道「我在什么场景最危险」。
3. **急救必须低摩擦**：从点开到开始干预 ≤ 2 次点击。
4. **复吸不是失败**：产品语言要去羞辱化，强调「一次失误 ≠ 全盘重来」。
5. **医疗边界清晰**：药物、剂量、戒断处理交给医生。

## 4. 研究结论：有效的戒烟方法

### 4.1 总原则

1. **设定明确戒烟日，一次性停吸**通常优于无限期逐步减量；逐步减量可作为无法突然停吸者的备选。
2. **组合优于单一**：药物 + 行为支持 + 环境改造。
3. **前 1–2 周最危险**，之后渴求频率和强度逐步下降。
4. **多数成功者经历多次尝试**，复吸后应分析触发因素并重新设定戒烟日。

### 4.2 方法证据表

| 方法 | 证据与效果 | 产品可承载形式 | 边界 |
|---|---|---|---|
| 伐尼克兰（处方药） | 一线；6 个月戒烟率约提高 2–3 倍 [高] | 科普、用药提醒、门诊导流 | 不推荐、不开方、不指导剂量 |
| 尼古丁替代 NRT | 一线；贴片 + 短效联合优于单一 [高] | 科普、提醒、门诊/药店导流 | 同上 |
| 安非他酮（处方药） | 一线；约提高 1.6 倍 [高] | 科普、门诊导流 | 同上 |
| 行为干预（CBT/动机访谈/简短建议） | 有效 [高] | 课程、急救脚本、复盘 | 不能替代专业治疗 |
| 戒烟热线/短信 | 有效；交互式短信在网络 Meta 分析中 RR 约 2.43 [中] | 一键拨号、短信提醒 | 依赖当地服务可用性 |
| 智能手机 App | 单独使用效果不确定（OR 1.25，未达显著）；App + 药物 OR 1.79 [中] | 本产品即属于此类 | 必须与药物/行为支持组合才有稳定效果 |
| 运动 | 急性运动可靠降低渴求，效果可持续约 30 分钟；长期戒烟率提升有限（RR 1.15）[中] | 5 分钟快走/开合跳/拉伸引导 | 心血管疾病患者需量力而行 |
| 电子烟 | 尼古丁电子烟比 NRT 更能帮助戒烟（RR 1.59，高确定性）；长期安全性数据有限 [高/中] | 仅做中立科普，不做销售/导购 | 中国未批准为戒烟药物；不建议非吸烟者使用 |
| 针灸/催眠/厌恶疗法 | 证据不足 | 不作为主推 | 可提及，不背书 |

### 4.3 内容红线

- 不宣称「治愈」「保证戒掉」「有效率 XX%」。
- 不推荐具体药物品牌、剂量、购买渠道。
- 不把电子烟包装成「无害」或「首选」。
- 不制造恐惧、不羞辱复吸者、不利用焦虑推销付费服务。
- 涉及精神疾病、孕期、心血管疾病、癫痫等人群，提示先就医。

## 5. 研究结论：触发场景与「顾不上抽烟」的情境

### 5.1 高风险触发场景

饭后、饮酒、咖啡、压力、焦虑、无聊、独处、社交递烟、看到别人吸烟、打牌/麻将、开车、打电话、工作间隙、如厕、起床后。

### 5.2 低渴求/「顾不上」的四类情境

> 说明：以下不是临床疗效结论，而是基于注意力占用与行为约束的设计推断。中心思想是「延迟渴求」而非「消除烟瘾」。

| 类型 | 例子 | 为什么有效 |
|---|---|---|
| 高认知负荷/心流 | 竞技游戏、编程排障、考试、写作、剪辑、演奏、手术、直播、紧急救火、深度对话 | 注意力被完全占据；目标清晰、反馈即时、难度匹配 |
| 身体被占用/环境禁烟 | 游泳、洗澡、按摩、理发、健身、跑步、球类、瑜伽、看电影、坐飞机、图书馆、无烟会议室、复杂路况开车、做饭洗碗、抱孩子、护理病人 | 手被占用 + 场所不允许 + 起身成本高 |
| 社交约束 | 与不吸烟者/长辈/孩子/客户在一起、面试、约会、正式场合 | 社会规范抑制 |
| 生理状态 | 剧烈运动后、感冒咽痛、刚刷牙、正餐吃饱、恶心、高原 | 身体本身排斥 |

**关键区别**：「顾不上」≠「不想」。活动结束后渴求可能反弹；重度依赖者甚至会中断心流去抽烟。因此它只能作为**急救工具**，不能作为治疗方法宣传。

### 5.3 对产品的设计含义

- 建立用户个人化的「替代活动清单」，来源是用户自己记录的「我在＿＿时最不想抽」。
- 渴求急救不能只有一条路径：先做 **10 秒分型**（习惯 / 情绪 / 社交 / 戒断 / 无聊 / 线索），再进入对应 3–5 分钟流程。
- 事前用 **if-then 计划**把高危场景与具体动作绑定；事中用 **urge surfing + 延迟承诺 + 感官替代**；事后记录有效性并更新个人工具包。
- 高危场景预警：饮酒、饭后、压力、社交、独处。
- 文案强调「先撑 10 分钟，再决定」，避免说教；完整机制见第 16 节。

## 6. 产品定位与设计原则

### 6.1 一句话定位

> 戒烟期间的「渴求急救工具 + 行为教练 + 医疗导流入口」。

### 6.2 设计原则

1. **循证**：功能背后有依据，区分证据与推断。
2. **低摩擦**：急救入口全局可达，2 次点击内开始。
3. **不羞辱**：复吸记录是数据，不是道德审判。
4. **隐私优先**：吸烟与健康数据敏感，最小化收集。
5. **医疗安全**：不诊断、不开方、不承诺疗效。
6. **可退出**：用户可以随时导出/删除数据。

### 6.3 明确不做（v1）

- 电子烟/尼古丁产品商城或导购。
- AI 诊断、自动开药、剂量建议。
- 疗效承诺、成功率排行榜。
- 公开羞辱式排行榜、罚款式打卡。
- 未经核实的偏方、排毒、清肺保健品推荐。

## 8. 信息架构与关键流程

### 8.1 底部导航（草案）

1. **今天**：戒烟天数、倒计时、全局「我想抽烟」按钮、今日任务。
2. **记录**：触发日志、渴求记录、复吸记录。
3. **进展**：里程碑、省钱、健康改善、触发画像。
4. **我的**：评估结果、戒烟计划、提醒设置、隐私、医疗资源。

### 8.2 首次使用流程

```
欢迎页 → 免责声明/隐私同意 → Fagerström 评估 → 吸烟史 → 设定戒烟日
→ 选择高危场景 → 生成准备清单 → 进入首页
```

### 8.3 渴求急救流程（核心）

```
点击「我现在想抽烟」
→ 10 秒分型：习惯 / 情绪 / 社交 / 戒断 / 无聊 / 线索
→ 选择渴求强度（0–10）
→ 进入对应分支的 3 分钟引导（urge surfing / 呼吸 / 拒绝话术 / 感官替代）
→ 10 分钟延迟承诺 + 计时器
→ 期间可调用：替代动作、支持者、急救包、短效 NRT 提醒（遵医嘱）
→ 10 分钟后重新评分
→ 结果：过去了 / 抽了 / 还在渴求
→ 记录触发场景、使用的策略、有效性
→ 若「抽了」：进入复吸复盘（不评判，防止破罐破摔）
```

### 8.4 复吸复盘流程

```
记录复吸 → 选择触发因素 → 当时在做什么 → 如果重来一次可以怎么做
→ 更新个人应对方案 → 保留历史 → 回到计划
```

## 10. 合规、安全与伦理

### 10.1 平台与资质（待核实）

- 微信小程序医疗健康类目可能要求相关资质；需在开发前核实。
- 若涉及医疗机构、医生入驻、处方导流，资质要求更高。
- 不能以「戒烟治疗」名义做未获批的医疗服务。

### 10.2 内容与语言

- 所有药物相关内容标注「处方药，请遵医嘱」。
- 不提供个体化用药建议。
- 不承诺疗效，不使用「治愈」「彻底戒断」等绝对化表述。
- 复吸相关文案去羞辱化。

### 10.3 心理安全

- 提供心理危机提示：若出现严重情绪低落、绝望、自伤念头，立即联系专业机构。
- 不把戒烟失败归因于用户人格。
- 对孕期、青少年、精神疾病共病人群，优先建议就医。

### 10.4 隐私

- 最小化收集；敏感数据加密；明确保存期限。
- 提供数据导出与删除。
- 不向第三方出售健康数据；广告不得基于吸烟状态精准投放。

### 10.5 利益冲突

- 不接受烟草、电子烟企业的赞助或推广。
- 商业模式（会员/机构合作）需公开，避免与戒烟目标冲突。

## 15. 平台决策：移动端 Web / PWA（2026-11-13）

### 15.1 为什么放弃微信小程序

| 因素 | 微信小程序 | 本机情况 |
|---|---|---|
| 开发工具 | 微信开发者工具（Electron） | 预计 1.5–2.5 GB 内存；本机总 3.9 GB，空闲 1.8 GB |
| 官方要求 | 建议 8 GB 内存 | 低于建议配置 |
| 附加成本 | 微信账号、AppID、审核/备案 | 增加复杂度 |
| 结论 | 可启动但体验差 | 不作为首选 |

### 15.2 目标形态

- 移动端优先的响应式网页（H5），单页应用。
- 可安装 PWA：手机浏览器“添加到主屏幕”，全屏/独立窗口运行。
- 离线可用（Service Worker 缓存），数据本地优先（localStorage / IndexedDB）。
- 无需 Node、无需构建工具；一个 `index.html` 即可开发与预览。

### 15.3 技术方案（MVP）

| 层 | 方案 |
|---|---|
| 结构 | 单文件 `index.html`，内联 CSS/JS；后续可拆分 |
| 路由 | hash 路由（`#/today`、`#/rescue` 等），无服务端 |
| 状态 | 原生 JS + 简单 store；localStorage 持久化 |
| 数据 | 评估、触发日志、渴求记录、复吸记录；支持导出/导入 JSON |
| PWA | `manifest.webmanifest` + `service-worker.js` + 图标 |
| 兼容 | iOS Safari 15+、Android Chrome 100+、Edge 100+ |
| 开发 | 系统 Edge 打开本地文件；手机通过局域网静态服务器预览 |

### 15.4 手机安装方式

- **Android Chrome**：菜单 → “安装应用”或“添加到主屏幕”。
- **iOS Safari**：分享 → “添加到主屏幕”；需 `apple-mobile-web-app-capable` 等 meta。
- 真正的独立窗口/离线需要 **HTTPS** 托管（localhost 除外）。

### 15.5 托管与发布（待定）

- 需要 HTTPS 静态托管；候选：Gitee Pages、腾讯云 COS、阿里云 OSS、Cloudflare Pages。
- 国内访问优先考虑腾讯云/阿里云；自定义域名可能涉及备案。
- 首发可先用临时静态托管 + 手机添加到主屏幕验证 MVP。

### 15.6 PWA 的限制（必须在产品中如实说明）

- iOS 的 Web Push 仅在“已添加到主屏幕”且 iOS 16.4+ 时支持，可靠性不如原生 App。
- 无应用商店分发；无法使用微信登录/分享/支付等原生能力。
- 浏览器可能清理本地存储；必须提供导出/导入备份。
- 不能承诺后台提醒一定送达；核心急救流程必须在打开页面时可用。

### 15.7 对 MVP 功能的影响

- P0 功能不变：评估、戒烟日、触发日志、渴求急救、里程碑/省钱、复吸复盘、医疗导流。
- 去掉小程序特有的登录、订阅消息、微信分享；改为本地数据 + 可选导出。
- 医疗合规仍适用：不宣称疗效、不提供处方建议、心理危机提示。

### 15.8 下一步

1. 确认本方案（Web/PWA）后，产出页面原型与交互说明。
2. 写第一版单文件 `index.html`（仍属原型，不是最终代码）。
3. 手机实测“添加到主屏幕”与离线缓存。

## 16. 渴求控制机制 2.0（2026-11-13）

> 目标：把「想抽烟时靠意志力硬扛」改为「事前有预案、事中有分支、事后有学习」的闭环。证据等级标注：高 / 中 / 推断。

### 16.1 现有设计的问题

1. **单一路径**：60 秒呼吸 + 替代活动，对所有渴求类型一视同仁。
2. **只处理当下**：没有事前 if-then 预案，用户仍靠临场意志力。
3. **延迟太短**：5 分钟只覆盖渴求峰值，未覆盖“峰值后仍想抽”的情况。
4. **缺少分型**：习惯性动作、情绪调节、社交递烟、戒断、无聊需要的策略不同。
5. **缺少感官替代**：只靠“做点别的”，没有口/手/身体的具体替代物。
6. **缺少社会支持与承诺装置**：独自硬扛，失败后容易自责。
7. **缺少事后学习**：没有记录“哪种策略对我有效”，无法个性化。
8. **缺少破罐破摔防护**：一次失误容易演变为全面复吸。
9. **缺少药物衔接**：使用 NRT 的人不知道在渴求时用短效剂型。
10. **只有被动响应**：没有高危场景的主动预警。

### 16.2 设计目标

- 低摩擦：2 次点击内开始，离线可用。
- 分型：先判断“这是哪一种渴求”，再给对应方案。
- 个性化：基于用户自己的触发场景与历史有效策略。
- 短：3–5 分钟一个动作，10 分钟一个决策点。
- 不羞辱：复吸是数据，不是人格失败。
- 医疗安全：药物只做提醒与导流，不开方。

### 16.3 三层机制总览

| 层 | 时机 | 核心动作 | 产品形态 |
|---|---|---|---|
| 事前 | 日常 / 高危前 | 识别触发、if-then 计划、环境改造、急救包、承诺装置 | 计划页、预警、清单 |
| 事中 | 渴求发作 | 10 秒分型 → 3 分钟技能 → 10 分钟延迟 → 升级支持 | 急救流程、计时器、音频 |
| 事后 | 结束后 | 记录有效性、即时强化、更新个人工具包、复吸复盘 | 记录页、周报 |

### 16.4 事中分型与分支

| 类型 | 用户自述 | 3 分钟动作 | 升级动作 |
|---|---|---|---|
| 习惯 / 自动化 | “手自动就去拿了” | 打断动作链：起身、换房间、喝水、刷牙、双手占用 | 移除身边的烟 / 打火机 |
| 情绪 / 压力 | “烦、焦虑、想放松” | 90 秒 urge surfing + 4-7-8 呼吸 + 冷水洗脸 + 命名情绪 | 联系支持者；必要时就医 |
| 社交 / 递烟 | “别人递给我 / 大家都在抽” | 拒绝话术 + 离开或换位 + 手握水杯 | 提前准备拒绝脚本；少去高危局 |
| 戒断 / 生理 | “心慌、坐立不安、注意力散” | 喝水、咀嚼、快走 5 分钟；按医嘱使用短效 NRT | 戒烟门诊 / 医生 |
| 无聊 / 空虚 | “没事干，就想点一支” | 5 分钟微任务：收拾桌面、洗碗、一组开合跳、打电话 | 建立“无聊替代清单” |
| 线索 / 条件反射 | “饭后 / 咖啡 / 酒 / 开车 / 电话” | 改变配套动作：饭后刷牙散步、咖啡换茶、开车不带烟 | 重新设计日常路线与习惯 |

> 设计推断：分型本身不是疗效保证，但能让建议更具体、更易执行。

### 16.5 核心技能脚本

**A. Urge surfing（冲动冲浪，3 分钟）**

- “不用赶走它，只要观察它。”
- 找到冲动在身体的部位（喉咙、胸口、手），描述温度 / 紧度。
- 给强度打分 0–10，观察它上升、达到峰值、再下降。
- 提醒：“冲动像波浪，峰值通常几分钟，我不需要服从它。”
- 结束时再评分；若下降，记录“我熬过了一波”。

**B. 10 分钟延迟承诺**

- 文案：“先给自己 10 分钟。10 分钟后如果你还想抽，再决定。”
- 这不是“永远禁止”，而是降低对抗感、争取前额叶上线的时间。
- 计时期间必须做一个具体动作（不是干等）。
- 10 分钟后重新评分：下降 → 强化；不变 / 更高 → 升级支持。

**C. 4D**

- Delay 延迟、Deep breathe 深呼吸、Drink water 喝水、Do something else 换件事。
- 作为兜底口诀，不替代分型。

**D. 认知解离**

- 把“我需要抽一支”改成“我注意到我有了想抽烟的念头”。
- 把“抽烟能缓解压力”改成“抽烟只是把压力推迟 10 分钟”。

**E. 感官替代**

- 口：水、无糖口香糖、吸管、牙签。
- 手：压力球、笔、橡皮筋。
- 身体：快走、开合跳、拉伸、冷水洗脸。
- 社交：给支持者发一条消息。

**F. 拒绝递烟话术**

- “我在吃药，医生不让。”
- “戒了，闻着难受。”
- “我刚刷过牙。”
- 配合离开 / 换位 / 手里拿杯子。

### 16.6 事前：if-then 计划与环境改造

- 每个高危场景写一条 **如果……那么……**：
  - 如果饭后想抽，我就立刻刷牙并出门走 5 分钟。
  - 如果同事递烟，我就说“戒了，闻着难受”，然后去接水。
  - 如果晚上喝酒，我就提前告诉朋友我在戒烟，并只拿水杯。
- 环境改造：清理烟、打火机、烟灰缸；设定无烟区；避开吸烟角。
- 急救包：口香糖、吸管、压力球、水杯、理由卡片。
- 理由卡片：写下 3 个最重要的戒烟理由（健康、家人、钱、形象）。
- 承诺装置（可选）：支持者见证、戒烟契约、节省的钱转入奖励基金。
  - 证据混合，避免羞辱性 / 过度惩罚设计。

### 16.7 事后：学习与强化

- 每次急救后记录：类型、强度前后、使用策略、有效性 1–5、结果。
- 成功熬过：即时正反馈 + 积分 / 省钱里程碑；不要只奖励“戒了多久”，也奖励“熬过一波”。
- 每周生成“个人触发画像”：高危时段 / 场景、最有效策略、失败模式。
- 复吸复盘：分析触发链，不归因人格；更新 if-then 计划；防止“破罐破摔”。
- 一次失误 ≠ 全面复吸；重点是下一支不抽。

### 16.8 主动预警（P1）

- 基于历史触发日志，在高危时段前 10–15 分钟推送预案（饭后、周五晚、酒局、压力事件）。
- iOS PWA 推送受限；优先做打开 App 时的“今日高危提醒”，不承诺后台必达。
- 设计推断：JITAI 有价值，但证据仍在积累，不能夸大效果。

### 16.9 数据与指标

- 渴求次数 / 日、强度分布、分型分布。
- 急救使用率、完成率、10 分钟延迟完成率。
- 每次延迟时长、累计延迟时长、最长延迟、平均延迟、熬过波数、高渴求胜利次数。
- 本周 vs 上周延迟趋势；难度调整后的延迟（时长 × 起始渴求强度 / 10）。
- 急救后 30 分钟复吸率、当日复吸率。
- 策略有效性排名（按类型）。
- 自我效能评分（0–10）。
- 7 日 / 30 日戒断率。

### 16.10 MVP 取舍

**P0 新增 / 强化**

- 10 秒分型（6 类）。
- 延迟阶梯：3 分钟 / 10 分钟 / 做任务 / 玩一局 / 我现在就要抽。
- 3 分钟 urge surfing 文字 / 音频。
- 任务库与 2–3 分钟小游戏（不设“赢了才能抽”的硬门槛）。
- 个人 if-then 计划（3–5 条）。
- 感官替代清单（口 / 手 / 身体 / 社交）。
- 急救后有效性评分与即时强化。
- 每轮延迟记录（时长、起始/结束强度、任务）。
- 即时称赞（具体、过程性、非人格化）。
- 与上次 / 近 7 日平均对比，附安全降级文案。
- 延时统计页（累计、最长、平均、熬过波数、趋势）。
- 复吸复盘 + “下一支不抽”协议。
- 始终可见的“我现在要抽”与一键记录。
- 支持者一键联系 / 戒烟热线。

**P1**

- 高危时段预警、个性化策略推荐、承诺装置、NRT 用药提醒、周报。

### 16.11 证据与边界

| 组件 | 证据 | 说明 |
|---|---|---|
| Urge surfing / 正念 | 中 | 作为渴求管理技能，非治愈承诺 |
| Implementation intentions（if-then） | 中–高 | 目标达成研究支持较强，需具体可执行 |
| 4D / 分散注意力 | 临床常用 | 短期桥梁，不能单独作为长期方案 |
| 急性运动 | 中–高 | 5–30 分钟中高强度，短期降低渴求 |
| 短效 NRT | 高 | 对突发渴求有效；需遵医嘱 / 说明书 |
| 社会支持 | 中–高 | 支持者、热线、同伴 |
| 承诺装置 | 混合 | 可能有效，避免羞辱 / 过度惩罚 |
| JITAI 主动预警 | 推断 | 有前景，证据有限 |

> 医疗边界：以上为行为支持设计，不构成医疗建议；药物使用由医生 / 药师评估。

## 17. 急救交互 2.1：延迟阶梯、游戏与任务清单（2026-11-13）

### 17.1 你提出的两个方案

**方案 A：延迟 + 游戏循环**

想抽烟 → 系统建议 10 分钟后再抽 / 玩一个有难度的游戏 → 游戏赢了再问是否还想抽 → 想抽且不愿再等 → 记录一支；愿意等 → 再 10 分钟或再玩一局。

**方案 B：转移注意力任务**

想抽烟 → 推荐几件转移注意力的事（如 10 个深蹲）→ 完成后还想去 → 再给一组 → 不愿坚持 → 点击“立即抽烟” → 记录一支。

### 17.2 评估

| 方案 | 优点 | 风险 |
|---|---|---|
| A 延迟 + 游戏 | 延迟符合渴求管理；游戏能占据注意力；循环给多次机会 | “赢了才能抽”会把烟变成奖励；难度过高会挫败/激怒；10 分钟可能太长；无限循环像操纵 |
| B 任务清单 | 灵活、低成本；体力活动有短期降低渴求的证据；容易在 PWA 实现 | 任务可能不合场景（上班/地铁）；重复像惩罚；纯 distraction 不处理情绪根源 |

### 17.3 推荐：延迟阶梯 + 任务 / 游戏混合

不要二选一，也不要“赢了才能抽”。推荐把两者合成一个**延迟阶梯**：

1. **不把游戏胜利当成“允许抽烟”的兑换券**。游戏只是延迟工具；赢了是“闯过一波”，不是“获得一支”。
2. **时间可选**：3 分钟（快速急救）/ 10 分钟（标准延迟）。高强度渴求先用 3 分钟，避免 10 分钟太长导致放弃。
3. **任务或游戏二选一**：用户自己选，不强制。
4. **每轮结束重新评分**：0–10；下降 → 强化；不变/更高 → 再一轮或升级支持。
5. **最多 3 轮**，避免无限循环和操纵感；第 3 轮后给出“记录一支 / 联系支持者 / 再撑 10 分钟”的选择。
6. **始终显示“我现在要抽”**，不隐藏、不羞辱；点了就一键记录。
7. **记录后给下一步**：“下一支不抽”的 if-then 计划，而不是清零和自责。

### 17.4 交互状态机

```
[首页] 点击“我想抽烟”
→ [选择] 先撑 3 分钟 / 先撑 10 分钟 / 给我一个任务 / 玩一局 / 我现在要抽
→ [执行] 计时 + urge surfing / 任务 / 小游戏
→ [复评] 现在还想抽吗？0–10
   ├─ 0–3：记录“熬过一波” → 奖励 → 显示理由卡 → 结束
   ├─ 4–7：再一轮（换一种任务/游戏）或 联系支持者 或 我现在要抽
   └─ 8–10：再撑 10 分钟 / 联系支持者 / 我现在要抽
→ [记录] 点击“我现在要抽” → 一键记录一支
→ [复盘] 可选：触发场景 / 情绪 / 下一支的 if-then 计划
```

### 17.5 游戏化设计原则

- **低挫败**：简单、可暂停、难度可调；不要 PvP、不要高难度反应挑战。
- **短**：2–3 分钟一局，适配碎片时间。
- **无失败惩罚**：输了也能进入下一步；不说“你失败了”。
- **不出戏**：不要用烟草相关元素作为奖励或道具。
- **不赌博**：不做抽奖、开箱、随机奖励。
- **单手可玩**：走路、排队、上班间隙都能用。
- **可离线**：PWA 缓存，无网络也能玩。
- **游戏只是“占据注意力”**，真正的技能仍是 urge surfing / 延迟 / 认知解离。

可考虑的小游戏类型：反应力、记忆配对、气泡点击、2048 类、节奏呼吸、简单拼图。避免高唤醒、强竞争、容易激怒的游戏。

### 17.6 任务库设计

| 类别 | 示例 | 适用场景 |
|---|---|---|
| 身体 | 10 个深蹲、20 个开合跳、拉伸、快走 5 分钟、冷水洗脸 | 在家/办公室/户外 |
| 手部 | 洗碗、收拾桌面、叠衣服、捏压力球、涂鸦 | 手空闲时 |
| 口腔 | 喝水、刷牙、无糖口香糖、吸管 | 饭后/开会前 |
| 认知 | 从 100 倒着减 7、说出 5 样看到的东西、列明天 3 件事 | 不能起身时 |
| 社交 | 给朋友发消息、给家人打电话、回复一条消息 | 独处/无聊 |
| 环境 | 离开房间、去无烟区、开窗、出门走一圈 | 有人递烟/酒局 |
| 创意 | 写 3 条戒烟理由、画一笔、弹一段乐器 | 在家/有工具时 |
| 游戏 | 2–3 分钟小游戏 | 需要强注意力时 |

规则：

- 每次给 **3 个选项**，用户自己选；不命令“去做 10 个深蹲”。
- 根据场景过滤（上班、地铁、家里、户外、有人在场）。
- 任务时长 3–5 分钟；完成后必须回到“还想抽吗”的复评。
- 同一任务不要连续重复超过 2 次，避免惩罚感。
- 任务不是“治疗”，只是延迟和注意力转移；要配合 urge surfing。

### 17.7 防挫败与防操纵

- 不做“必须赢”的硬门槛；用户有权跳过。
- 不隐藏“我现在要抽”；尊重自主权。
- 不无限循环；最多 3 轮。
- 不用羞辱性文案（“你又失败了”“你真没毅力”）。
- 不用虚假稀缺/倒计时胁迫。
- 记录一支后仍然保留计划和历史，不清零。

## 18. 自报数据与监督问题（2026-11-13）

### 18.1 结论

**无法真正监督，也不应该把产品做成监控。** 用户完全可以抽烟但不记录。与其追求“ verification”，不如设计一个**让用户愿意诚实记录**的产品；如果用户不想诚实，任何技术都救不了。

### 18.2 用户不记录的原因

- 羞耻 / 怕被评判
- 怕连续天数清零、怕“失败”
- 记录太麻烦
- 担心隐私（尤其涉及家人/伴侣）
- 自我欺骗（“这一支不算”）
- 觉得记录了也没用

### 18.3 提高诚实记录的 8 个设计

1. **一键记录**：首页始终有“我抽了一支”，点一下完成；详情可跳过。
2. **去羞辱化语言**：用“记录一支”“一次失误”，不用“破戒”“失败”。
3. **记录后立即给价值**：马上显示“你这周的触发规律 / 下一支的应对建议”，让记录有用。
4. **本地优先 + 隐私**：默认只存在手机本地；不公开、不排行榜；用户可导出/删除。
5. **不用连续天数惩罚**：用“累计无烟天数”“最近一次”“熬过多少波”替代“连续 30 天断了就归零”。
6. **诚实框架**： onboarding 明确说“数据只用于帮你找规律，不评判”；可让用户自己选“我愿意如实记录”。
7. **可选支持者**：用户主动选择一位朋友/家人，只在用户同意时同步里程碑或求助，不做每日监控。
8. **奖励记录本身**：不只奖励“没抽”，也奖励“如实记录 + 复盘”，因为数据越准，建议越准。

### 18.4 可选的轻量验证（不是 MVP）

| 手段 | 能验证什么 | 局限 |
|---|---|---|
| CO 呼气测试 | 最近数小时是否吸烟 | 需设备/药店/门诊；不能日常化 |
| 支持者确认 | 社交层面的见证 | 依赖关系；可能变成监控，伤害信任 |
| 承诺金 / 押金 | 提高违约成本 | 证据混合；可能引发焦虑/隐瞒；需自愿、可退出 |
| 智能打火机/烟灰缸 | 使用次数 | 贵、隐私、可绕过 |
| 可穿戴手势检测 | 手到嘴动作 | 研究阶段，误判高 |
| 唾液/尿液可替宁 | 数天内尼古丁暴露 | 需实验室，侵入性，不适合日常 |

### 18.5 不做什么

- 不做拍照证明、随机查岗、位置追踪。
- 不做公开羞辱、排行榜倒数、罚款式惩罚。
- 不做“说谎检测”。
- 不把支持者变成警察。
- 不因为一次记录就清零全部进度。

### 18.6 MVP / P1 取舍

**MVP**

- 一键“我抽了一支” + 可选触发/情绪。
- 去羞辱化文案与“下一支不抽”计划。
- 记录后的个性化洞察（触发时段/场景）。
- 本地存储、导出/导入、删除。
- 不用连续天数惩罚。

**P1**

- 可选支持者（里程碑/求助同步）。
- 承诺装置（自愿、可退出）。
- CO 测试/门诊数据接入（如果合作方支持）。
- 周报与触发画像。

> 关键认知：**自报数据是产品的数据源，不是需要被“抓包”的证据。** 产品越像警察，用户越会撒谎；产品越有用，用户越愿意说真话。

## 19. 延时记录、称赞与对比机制（2026-11-13）

### 19.1 目标

- 强化“延迟”这个动作本身，而不只奖励“最终没抽”。
- 让用户看到自己的进步，但不因某次变短而羞耻。
- 为个性化推荐积累数据：哪种任务、哪个时段、哪种渴求强度下，延迟更有效。
- 避免把鼓励做成“控制性奖励”，削弱内在动机。

### 19.2 记录什么

| 层级 | 字段 |
|---|---|
| 每轮 DelayRound | 开始/结束时间、延迟秒数、起始/结束渴求强度、任务类型、是否完成、结果 |
| 每次 Episode | 总延迟秒数、轮次、最高渴求、最终结果（熬过/抽了）、是否复吸 |
| 长期 UserStats | 累计延迟、最长延迟、平均延迟、熬过波数、高渴求胜利次数、上次延迟、个人最佳 |

说明：

- “熬过波数” = 完成一轮延迟且最终没有抽的轮次。
- “高渴求胜利” = 起始渴求 ≥ 7 分，仍完成至少 3 分钟延迟。
- 记录必须一键完成；详细字段可跳过。

### 19.3 称赞设计

原则：

1. **即时**：计时结束马上反馈，不要等用户写完表单。
2. **具体**：说清楚“做了什么 + 数据变化”，不是空泛“你真棒”。
3. **过程/努力导向**：夸行为、策略、坚持，不夸人格。
4. **短**：一两句话，不打断下一步。
5. **多样**：文案轮换，避免机械重复。
6. **自主**：提供“低调模式”，允许用户关掉夸张庆祝。
7. **不夸大**：延迟是进步，不是“治愈”；不承诺健康效果。
8. **默认语气：鼓励型 + 积极预期**：先肯定这次做到的事，再给一个具体、可信的“下次也能做到”的预期；不空喊“你一定能戒掉”，也不承诺“以后永远不想抽”。

> 已确认：默认使用鼓励型 + 积极预期语气；用户可在设置中切换为低调/中性。

示例：

| 场景 | 推荐文案 | 避免 |
|---|---|---|
| 完成 10 分钟，渴求下降 | “你从 8 分熬到 4 分，用了 10 分钟。呼吸 + 起身走动对你有效——下次渴求再来，你已经有办法了。” | “你真棒”（空泛） |
| 完成 3 分钟，渴求仍高 | “起始 9 分，你还是撑了 3 分钟。下次可以先从 3 分钟开始，不需要一次扛 10 分钟。” | “才 3 分钟” |
| 完成延迟但最终抽了 | “你先争取了 10 分钟，这 10 分钟不是白费。下一支我们再用这个办法，你已经证明自己做得到。” | “还是抽了，前功尽弃” |
| 比上次短 | “这次 6 分钟，上次 10 分钟；但这次起始渴求 9 分（上次 6 分），难度更高。下次 6 分时你大概率能撑更久。” | “你退步了” |
| 第一次记录 | “这是你的第一个延迟基线：X 分钟。下次我们就能看到变化。” | “太少了” |
| 高渴求下坚持 | “9 分渴求还能撑 5 分钟，这是一次高难度胜利。下次高渴求时，先想起这次。” | 只比时长、不看强度 |

### 19.4 对比逻辑

**核心原则：只把“更多”做成庆祝；把“更少”做成理解 + 上下文。**

| 情况 | 处理方式 |
|---|---|
| 比上次多 | 明确说“比上次多坚持 X 分钟”，庆祝 |
| 和上次一样 | “和上次一样稳”，肯定稳定性 |
| 比上次少 | 不评价“退步”；补充起始渴求、场景难度；同时展示累计/平均 |
| 第一次 | 只建立基线，不比较 |
| 高渴求下较短 | 用“难度调整”视角：时长 × 起始强度 / 10 |
| 最终抽了 | 仍然称赞已争取到的延迟；不把延迟清零 |

**默认展示：与上次对比。** 优先同类型场景（如“饭后”）；没有同类型则用上一次任意场景；首次只显示基线。

对比维度（默认上次，其他可切换）：

- 上次同类型场景（如“饭后”）——默认。
- 近 7 日平均。
- 个人最佳。
- 累计延迟总时长。
- 本周 vs 上周。

展示位置：

- **延迟结束卡片默认显示上次对比**（如“本次 10 分钟 · 上次 8 分钟 · +2 分钟”）。
- “我的延时”详情页可切换平均/最佳/周对比。
- 比上次短时，卡片仍显示两者数字，但文案给上下文，不做负面标题。

避免：

- 公开排行榜、好友排名。
- 只拿“上次”当唯一标准。
- 用“少坚持了 X 分钟”做负面标题。
- 把延迟时长直接等同于“意志力”。

### 19.5 展示设计

- **每次延迟结束**：庆祝卡片（时长 + 一句具体称赞 + 一个有效策略 + 与上次/平均的对比）。
- **“我的延时”页**：累计延迟、最长、平均、熬过波数、高渴求胜利、7 日柱状图。
- **周报**：本周 vs 上周、最有效任务、高危时段、下一步建议。
- **可选“延时银行”**：累计分钟数解锁徽章/内容；不要用烟作为奖励，不要做成控制性经济系统。

### 19.6 证据与风险

- **自我决定理论**：胜任感、自主性、归属感支持内在动机；称赞应是信息性的，而不是控制性的。
- **过程称赞 vs 人格称赞**：夸“你用了什么方法、坚持了什么”比“你真聪明/真棒”更稳。
- **过度理由效应**：可预期的、控制性的物质奖励可能削弱内在动机；奖励要轻、以反馈为主。
- **社会比较**：自我比较（和过去的自己）通常比与他人比较更安全；避免排行榜。
- **游戏化**：整体效果中等，存在新鲜感衰减；不能替代药物/行为支持。

> 以上为设计推断与行为科学常识，不是临床疗效结论。

### 19.7 MVP / P1

**MVP**

- 每轮延迟记录（时长、强度前后、任务）。
- 即时、具体、过程性的称赞；默认鼓励型 + 积极预期。
- **与上次对比默认显示**：更多就庆祝；更少则给上下文 + 展示累计/平均。
- “我的延时”基础统计。

**P1**

- 7 日/30 日趋势、周报、徽章。
- 自定义称赞语气（低调/热情）。
- 按场景类型的对比（饭后、社交、压力等）。
- 数据导出。

## 20. 首页数据与展示设计（2026-11-13）

### 20.1 设计原则

- 首屏只放 **3–5 个核心数字**，不要堆成仪表盘。
- 只展示“能解释、能行动”的指标；不为了好看而编数字。
- 全部标注“约 / 估算”，不伪装精确。
- 不羞辱：复吸不清零全部进度；不用连续天数做惩罚。
- 目的：让用户看到“我在变好”，而不是“我又欠了多少”。

### 20.2 核心指标定义

| 指标 | 定义 | 口径 / 注意 |
|---|---|---|
| 戒烟第 X 天 | 从戒烟日起算（含今天） | 即使复吸也保留“戒烟旅程第 X 天” |
| 累计无烟天数 | 已完成的、无吸烟记录的天数（不含今天） | 与“第 X 天”分开显示 |
| 当前连续无烟 | 最近一次吸烟后的连续天数 | 放次要位置，不做惩罚 |
| 估算少抽支数 | `max(0, 基线日均 × 已完成戒烟天数 - 实际吸烟支数)` | 首日为 0，今天不算完整一天；无每日记录时用“延迟成功波数”作下限 |
| 估算省钱 | 少抽支数 × 单支价格 | 单支价格 = 包价 / 每包支数（默认 20），用户可改 |
| 延迟总时长 | 所有 `DelayRound` 秒数之和 | 含未成功的延迟；成功波数另算 |
| 熬过波数 | 完成延迟且最终未吸烟的轮次 | 每次急救可有多轮 |
| 高渴求胜利 | 起始渴求 ≥ 7 分且延迟 ≥ 3 分钟 | 单独计数，避免只看时长 |
| 下一个里程碑 | 1 天 / 3 天 / 1 周 / 2 周 / 1 月 / 3 月 / 6 月 / 1 年 | 显示倒计时 + 进度条 |
| 自我效能 | 0–10 自评 | 周趋势，不参与排名 |
| 复吸恢复 | 上次吸烟后已过天数 | 温和展示，不置顶 |

### 20.3 “预计多久彻底戒掉”怎么处理

**不建议做精确日期预测。** 医学上更常用“持续戒断”（如 7 天、30 天、6 个月、1 年）而不是“彻底戒掉”；个体差异大，给定日期容易造成“没达标=失败”的挫败。

替代方案：

1. **下一个持续戒断里程碑倒计时**：距离 7 天 / 30 天 / 90 天 / 180 天 / 365 天还有多久。
2. **阶段进度**：准备期 → 行动期 → 维持期，显示当前阶段与下一阶段。
3. **趋势描述**：例如“最近 7 天渴求次数下降 30%”，不承诺日期。
4. **自我效能变化**：用户对自己“下次能扛住”的信心。
5. 如果用户坚持要估算：给**区间** + 明确标注“估算，不构成医学预测”，且不要放在首屏主视觉。

避免：

- “还有 37 天彻底戒掉”这种假精确。
- 把“彻底戒掉”作为唯一成功标准。
- 用倒计时制造焦虑。

- 不把“少抽支数”换算成“多活多少天”。

## 22. 数据采集、效果统计与研究模块（2026-11-13）

### 22.1 结论

要做“哪种转移注意力方式对更多人有效”，**需要新增模块**，而且不是单个页面，而是一组能力：

- 个人效果：可以在本地算，属于 P0。
- 群体效果：需要 **匿名事件采集 + 同意与隐私 + 后端 + 统计分析 + 管理后台**，属于 P1/P2。
- 如果要做因果结论（“哪种方法有效”），还需要**随机分配任务 + 预注册分析**，否则只能叫“相关/观察”。

### 22.2 模块清单

| 模块 | 用户可见 | 作用 | 阶段 |
|---|---|---|---|
| 事件采集（前端埋点） | 否 | 记录渴求、任务、延迟、结果 | P0 |
| 同意与隐私中心 | 是 | 本地使用同意、匿名研究 opt-in、导出/删除 | P0 |
| 个人效果计算 | 是 | “对你最有效的 3 个方法” | P0/P1 |
| 后端接收 | 否 | 接收匿名事件 | P1 |
| 分析管线 | 否 | 聚合、模型、置信区间 | P1 |
| 管理后台 | 否（内部） | 查看任务效果、数据质量、版本 | P1 |
| 实验分组 | 部分 | 随机分配任务，估计因果效果 | P1 |
| 任务库版本管理 | 否 | task_id / version，避免版本混淆 | P1 |
| 研究导出 | 否 | 匿名 CSV/API | P2 |

### 22.3 事件模型（最小集）

| 事件 | 关键字段 |
|---|---|
| `craving_started` | craving_id、时间、触发类型、起始强度、场景、入口 |
| `triage_completed` | 分型、起始强度 |
| `intervention_assigned` | task_id、task_version、task_type、时长、分配方式（用户选择/随机） |
| `intervention_started` | 开始时间 |
| `intervention_completed` | 完成时间、实际时长、是否完成 |
| `craving_reevaluated` | 结束强度、是否还想抽 |
| `delay_round_completed` | 轮次、延迟秒数、是否继续 |
| `cigarette_logged` | 支数、触发、场景、是否复吸 |
| `day_summary` | 日期、无烟/记录、渴求次数、延迟总秒数 |

公共字段：

- `anon_user_id`（随机安装 ID，不含手机号/微信）
- `session_id`
- `timestamp`、`timezone_bucket`（只到城市/时区，不精确位置）
- `app_version`、`task_version`
- `device_class`（手机/平板/桌面）
- **不采集**：姓名、手机号、身份证、精确 GPS、通讯录、自由文本中的可识别信息。

### 22.4 效果指标与统计

- 任务完成率。
- 渴求下降：`before - after`（绝对值和百分比）。
- 延迟成功：完成该轮且 30 分钟内未记录吸烟。
- 30 分钟复吸率、次日吸烟率。
- 按 **任务 × 触发类型 × 起始强度** 分层。
- 个人效果：用户自己的历史对比，样本少时显示“数据不足”。
- 群体效果：混合效应模型 / 分层贝叶斯，用户作为随机截距；报告置信区间，不只报平均值。
- 小样本任务不排名，避免“3 个人用了就说有效”。

### 22.5 因果推断与实验设计

观察数据有强混杂：愿意做任务的人可能本来动机更强；做完任务的人可能本来就没那么想抽。要回答“哪种方法有效”，建议：

1. **随机分配**：在合适任务中随机推荐（用户仍可换），记录 `assignment_method=random`。
2. **ITT 分析**：按最初分配分析，而不是只分析完成者。
3. **分层**：按触发类型、起始强度、时段分层随机。
4. **预注册**：先写假设、主指标、样本量，再分析，避免 p-hacking。
5. 早期样本不足时，只展示个人效果，不发布群体排名。
6. 伦理：不能为了实验不给用户即时支持；“我现在要抽”始终可用。

如果做不到随机化，就只能说“观察到相关”，不能说“某方法有效”。

### 22.6 隐私与合规

- 吸烟与健康数据属于敏感个人信息；需要**明确、单独、可撤回**的同意。
- 本地使用同意与“匿名研究贡献”分开勾选；默认不参与研究。
- 最小化采集；随机 ID；聚合上报；小样本抑制（如 n<30 不展示）。
- 传输/存储加密；访问控制；保留期限；导出与删除。
- 不向第三方出售；不做基于吸烟状态的广告投放。
- 若发表研究：伦理审查/IRB、预注册、匿名聚合报告。
- 后端选址注意跨境数据传输合规；优先境内或合规区域。

### 22.7 MVP / P1 / P2

**MVP（本地，无后端）**

- 本地事件日志（同一套字段）。
- 个人效果计算与“最有效方法”。
- JSON 导出。
- 同意与隐私页；匿名研究开关先不做上传。

**P1（群体统计）**

- 匿名事件上传后端。
- 分析管线 + 管理后台。
- 任务库版本管理。
- “数据不足”状态与置信区间展示。

**P2（研究与因果）**

- 随机任务分配实验。
- 研究导出（CSV/API）。
- 预注册与伦理审查。

### 22.8 对 UI 设计稿的影响

- 新增 **首次使用 / 知情同意** 页面（本地使用 + 匿名研究分开）。
- 分型页增加 **起始渴求强度 0–10**。
- 延迟结束页增加 **结束强度**（已有复评，补上记录）。
- 设置页增加 **匿名研究** 开关。

- “最有效方法”标注“基于你的数据”，群体结论另做内部后台，不混在个人页。

### 24.2 静态包结构（最终应用）

```
site/quit-smoking/
├── index.html                 # 单文件应用（或入口）
├── manifest.webmanifest       # PWA manifest，scope = "./"
```

规则：

- 所有资源用**相对路径**（`./assets/...`），不要用 `/assets/...`。
- `manifest.webmanifest`：`start_url: "./"`、`scope: "./"`。
- Service Worker 注册：`navigator.serviceWorker.register("./sw.js", { scope: "./" })`。
- 不使用根路径的 `manifest`、`sw.js`、`favicon`，避免和根项目冲突。

### 24.3 Nginx 配置

假设文件在 `/var/www/quit-smoking/`：

```nginx
# 补斜杠，避免相对路径解析错误
location = /quit-smoking {
    return 301 /quit-smoking/;
}

location /quit-smoking/ {
    root /var/www;
    index index.html;
    try_files $uri $uri/ /quit-smoking/index.html;
}

# 静态资源缓存（可选）
location ~* ^/quit-smoking/.*\.(js|css|png|svg|webmanifest)$ {
    root /var/www;
    expires 30d;
    add_header Cache-Control "public, max-age=2592000";
}
```

注意：

- 不要改根 `location /`；只新增 `/quit-smoking/`。
- 修改后先 `nginx -t`，再 `systemctl reload nginx`。
- 如果使用 `alias`，`try_files` 容易出错，优先用 `root`。
- `index.html` 建议 `Cache-Control: no-cache`，避免更新后用户拿到旧页面。

### 24.4 Apache 配置（如果服务器不是 Nginx）

```apache
Alias /quit-smoking /var/www/quit-smoking
```

## 25. MVP 实现与部署包（2026-11-13）

### 25.1 已实现

功能范围：

- 首次使用：知情同意（本地使用 + 匿名研究可选项）。
- 设置：戒烟日、基线日均支数、烟价、每包支数、戒烟基金目标。
- 首页：戒烟第 X 天、4 个核心数字、下一个里程碑、今日洞察、戒烟基金。
- 渴求急救：入口弹层 → 10 秒分型 + 强度 → 3/10 分钟计时 / 任务 / 小游戏 → 延迟结束卡片（称赞 + 上次对比 + 复评）。
- 记录：一键记录一支、触发/情绪标签、“下一支不抽”提示。
- 进展：累计延迟、最长/平均、熬过波数、高渴求胜利、7 日柱状图、28 日无烟日历、触发画像。
- 设置：称赞语气、上次对比开关、匿名研究开关、导出 JSON、清除本地数据。
- 本地持久化：`localStorage`，无后端。

### 25.2 数据与计算口径

- 存储键：`quit-smoking.state.v1`。
- 少抽支数：`max(0, 基线日均 × 已完成戒烟天数 - 已记录吸烟支数)`；首日为 0，不预支今天。
- 累计无烟天数：只统计已完成的整天，不含今天。
- 省钱：少抽支数 × 单支价格（包价 ÷ 每包支数）。
- 延迟总时长：所有 `rounds.durationSec` 之和。
- 熬过波数：`completed = true` 的延迟轮次。
- 高渴求胜利：起始强度 ≥7 且延迟 ≥3 分钟。
- 所有统计标“估算”；没有每日吸烟日志时，少抽支数是近似值。
